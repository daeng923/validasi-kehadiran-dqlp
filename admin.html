Panduan Admin Console DQLP

Klik setiap bagian untuk melihat petunjuk penggunaan

Ringkasan keseluruhan kegiatan DQLP dalam satu halaman.

Kartu Statistik — Total peserta, presensi hari ini, jumlah skema, dan waktu update terakhir.

Grafik Unit & Homebase — Persentase kepatuhan kehadiran per unit kerja dan homebase. Gunakan kotak pencarian untuk filter.

Tren Kehadiran Per Periode — Grafik garis menunjukkan total hadir, rata-rata per peserta, dan capaian target per periode.

Rekap Per Pertemuan — Stacked bar chart kehadiran per pertemuan (Sabtu/Rabu/Kamis digabung satu pertemuan). Data diambil dari seluruh sheet RAW_PRESENSI.

Evaluasi Pimpinan — Analisis otomatis: penurunan/kenaikan signifikan, hari dengan absensi tinggi, konsistensi, dan perbandingan per hari.

Data di-refresh dengan klik tombol Refresh di setiap card, atau refresh keseluruhan saat login.

Tabel rekap kehadiran semua peserta dari Sheet1.

Kolom — NIP, Nama, Skema, Total Kehadiran, dan kolom per Periode yang terisi otomatis.

Pencarian — Ketik NIP atau nama di kolom pencarian untuk filter cepat.

Refresh — Klik tombol Refresh untuk menarik data terbaru dari server.

100 log presensi terbaru + aksi admin: validasi massal dan rekap presensi.

Tabel Log — Timestamp, NIP, Nama, Skema, Periode, Status, dan Validator. Klik Sync untuk data terbaru.

Validasi Massal — Mengubah semua status HADIR → VALID di RAW_PRESENSI. Kolom validator diisi "ADMIN SPREADSHEET" dan catatan "Di-bypass massal". Berguna jika pengajar lupa memvalidasi.

Rekap Presensi — Menghitung total kehadiran (VALID + HADIR_KEBIJAKAN) per peserta per periode dari RAW_PRESENSI, lalu menulis hasilnya ke kolom periode di Sheet1. Sama seperti menu "Rekap AIK" di spreadsheet.

Setelah Validasi Massal, jalankan Rekap Presensi agar total di Sheet1 terupdate. Urutan: Validasi dulu → baru Rekap.

Input presensi manual oleh instruktur/admin per skema dan tanggal.

1. Klik Muat Data untuk sinkronisasi data skema dan log dari server.

2. Pilih skema dari dropdown.

3. Di header kolom P-1 s/d P-14, set tanggal pertemuan. Kolom akan terbuka untuk diedit.

4. Klik sel untuk toggle status: kosong → ✓ Hadir → I Izin → A Alpha → kosong.

5. Tombol ✓ di header = set hadir semua (skip yang terkunci). Tombol ⌫ = kosongkan semua (skip terkunci).

6. Klik Konfirmasi Manual untuk menyimpan semua perubahan.

Sel dengan ikon gembok 🔒 adalah data hadir dari database yang tidak bisa diubah (audit lock).

Atur dan cetak daftar pengajar per pertemuan untuk keperluan bendahara.

1. Isi Pertemuan Ke, Tanggal, Periode, dan Catatan (opsional).

2. Klik Tarik dari Skema — tabel terisi otomatis dari data pengajar skema saat ini.

3. Jika ada pengajar yang berbeda di minggu ini, pilih dari dropdown Ganti Pengajar.

4. Klik Cetak — halaman langsung dicetak. Kolom dropdown otomatis disembunyikan saat cetak.

5. Klik Simpan Draft untuk menyimpan ke browser agar bisa dipanggil kembali.

Generate Riwayat Otomatis — membuat draft P1 sampai P(n) sekaligus dari data tanggal pertemuan yang sudah ada. Berguna untuk backfill pertemuan yang sudah lewat.

Generate sertifikat peserta per periode dan lihat riwayat yang sudah terbit.

Riwayat Sertifikat Terbit (atas) — Tabel semua sertifikat yang sudah digenerate dari LOG_SERTIFIKAT. Bisa dicari per NIP, nama, atau nomor sertifikat.

Generate Baru (bawah) — Pilih periode, lihat daftar peserta:

• Terbit — sudah punya sertifikat di periode ini.

• Belum Terbit — berhak generate (total kehadiran ≥10 per siklus).

• Belum Cukup — kehadiran belum mencapai 10.

Klik Generate per peserta, atau Generate Semua untuk batch.

Hak sertifikat = total kehadiran ÷ 10 (dibulatkan ke bawah). Misal hadir 25x = hak 2 sertifikat.

Rekap sertifikat lintas periode — lihat status setiap peserta di semua periode sekaligus.

1. Klik Muat Data (membutuhkan 30–60 detik karena memproses semua periode).

2. Tabel menampilkan status per periode: ✓ Terbit, Siap, atau jumlah kehadiran.

3. Filter berdasarkan skema atau cari peserta tertentu.

4. Tombol Generate Background (GAS) — proses di server tanpa browser terbuka, 10 sertifikat per 2 menit.

Generate data JSON untuk kebutuhan Infokom (integrasi ke sistem kepegawaian).

Generate — Membuat/update sheet DATA_INFOKOM di spreadsheet utama dengan format: nomor, nip, id_kegiatan, kegiatan, json.

Export Excel — Download file .xlsx dengan 2 sheet: Data Infokom (format template) dan Detail (mudah dibaca).

Konfigurasi kode presensi per sesi dari sheet SETTING_KODE. Admin mengganti kode dan toggle aktif/nonaktif setiap minggu.

Sesi Presensi — Kode untuk setiap sesi pertemuan (Sesi 1, Sesi 2, Sesi Rabu, dll). Toggle untuk aktif/nonaktif.

Fitur Khusus — IZIN (tanpa kode), QR (scan langsung), Kompensasi (kode khusus).

Edit Kode — Klik Edit, ketik kode baru, simpan.

Toggle — Geser switch untuk mengaktifkan/menonaktifkan sesi.

Kode yang aktif bisa digunakan peserta untuk presensi. Pastikan hanya kode yang sesuai jadwal yang diaktifkan.

Kelola data pengajar/instruktur DQLP dari sheet PENGAJAR.

Tabel — Daftar semua pengajar dengan email, nama, dan status aktif.

Edit — Klik Edit pada baris, form terisi otomatis. Ubah data lalu klik Update Pengajar.

Status — YA = aktif (muncul di dropdown skema), TIDAK = nonaktif.

Atur pengajar yang bertanggung jawab untuk setiap skema. Email otomatis dari rumus array spreadsheet.

1. Lihat tabel skema dengan pengajar saat ini.

2. Di kolom Ganti Pengajar, pilih nama pengajar baru dari dropdown (hanya pengajar aktif yang tampil).

3. Baris yang berubah ditandai warna dan badge nama baru.

4. Bisa ganti beberapa skema sekaligus, lalu klik Simpan N Perubahan.

Kolom email tidak diedit — otomatis mengikuti nama pengajar via rumus array di spreadsheet.

Token bersama untuk login pengajar ke halaman validasi kehadiran peserta.

Token — Satu token dipakai semua pengajar bersama. Klik ikon mata untuk tampilkan/sembunyikan.

Toggle Status — Aktif = pengajar bisa login. Nonaktif = semua akses pengajar diblokir (darurat).

Ganti Token — Ketik manual atau klik Acak untuk generate otomatis, lalu Simpan.

Salin — Klik ikon copy untuk menyalin token, lalu share ke grup WA pengajar.

Token tidak perlu diganti rutin — ganti hanya jika bocor atau ada kebutuhan keamanan. Nonaktifkan darurat jika perlu blokir akses sementara.
